# Codex Project Instructions

## Project
RMS Toy Robot Simulator — C# / .NET 10.

## Development methodology
Follow Spec-Driven Development (SDD).

The approved documents in `specs/` are the source of truth for implementation decisions.

## Workflow
1. Read the relevant specifications before making changes.
2. Propose an implementation plan before writing code.
3. Implement only approved requirements.
4. Write automated tests mapped to acceptance criteria.
5. Run tests and report results.
6. Update documentation when implementation decisions change.

## Engineering standards
- Use C# and .NET 10.
- Follow SOLID principles where they add value.
- Keep the solution simple and maintainable.
- Separate business logic from console I/O.
- Prefer readable code over unnecessary abstractions.
- Do not introduce external dependencies without justification.
- Do not add features outside the specification.

## AI usage transparency
- Record prompts used for code generation.
- Document significant AI-assisted design decisions.
- Do not claim tests passed unless they were executed successfully.
- Keep the submission consistent with the RMS challenge requirements.

## Important
Do not proceed from specification to implementation without explicit approval.
